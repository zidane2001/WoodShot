WOODSHOT DATABASE SCHEMA
========================

This file contains the complete database schema for the WoodShot e-commerce platform.
The schema supports all functionalities including user management, product catalog,
inventory tracking, order processing, delivery management, and admin operations.

TABLES:
-------

1. users
   - id: INTEGER (Primary Key, Auto-increment)
   - email: VARCHAR(255) (Unique, Not Null)
   - password_hash: VARCHAR(255) (Not Null)
   - first_name: VARCHAR(100) (Not Null)
   - last_name: VARCHAR(100) (Not Null)
   - phone: VARCHAR(20)
   - created_at: TIMESTAMP (Default: CURRENT_TIMESTAMP)
   - updated_at: TIMESTAMP (On Update: CURRENT_TIMESTAMP)
   - is_active: BOOLEAN (Default: TRUE)

2. addresses
   - id: INTEGER (Primary Key, Auto-increment)
   - user_id: INTEGER (Foreign Key -> users.id)
   - street: VARCHAR(255) (Not Null)
   - city: VARCHAR(100) (Not Null)
   - postal_code: VARCHAR(20) (Not Null)
   - country: VARCHAR(100) (Not Null)
   - latitude: FLOAT
   - longitude: FLOAT
   - is_default: BOOLEAN (Default: FALSE)

3. products
   - id: INTEGER (Primary Key, Auto-increment)
   - name: VARCHAR(255) (Not Null)
   - description: TEXT
   - wood_type: VARCHAR(100) (Not Null) // chêne, hêtre, bouleau, pin, érable, frêne, mixte
   - price_per_unit: DECIMAL(10,2) (Not Null)
   - unit: VARCHAR(50) (Not Null) // stère, kg, palette
   - stock_quantity: INTEGER (Default: 0)
   - image_url: VARCHAR(500)
   - specifications: JSON // humidity, density, calorific_value, cutting_type, storage_advice, burning_tips
   - is_available: BOOLEAN (Default: TRUE)
   - created_at: TIMESTAMP (Default: CURRENT_TIMESTAMP)

4. inventory
   - id: INTEGER (Primary Key, Auto-increment)
   - product_id: INTEGER (Foreign Key -> products.id, Unique)
   - quantity: INTEGER (Default: 0)
   - reserved_quantity: INTEGER (Default: 0)
   - last_updated: TIMESTAMP (On Update: CURRENT_TIMESTAMP)

5. orders
   - id: INTEGER (Primary Key, Auto-increment)
   - user_id: INTEGER (Foreign Key -> users.id)
   - address_id: INTEGER (Foreign Key -> addresses.id)
   - status: VARCHAR(50) (Default: 'pending') // pending, confirmed, preparing, shipped, delivered, cancelled
   - total_amount: DECIMAL(10,2) (Not Null)
   - order_date: TIMESTAMP (Default: CURRENT_TIMESTAMP)
   - delivery_date: TIMESTAMP
   - payment_status: VARCHAR(50) (Default: 'pending') // pending, paid, failed, refunded
   - tracking_number: VARCHAR(100) (Unique)

6. order_items
   - id: INTEGER (Primary Key, Auto-increment)
   - order_id: INTEGER (Foreign Key -> orders.id)
   - product_id: INTEGER (Foreign Key -> products.id)
   - quantity: INTEGER (Not Null)
   - unit_price: DECIMAL(10,2) (Not Null)
   - total_price: DECIMAL(10,2) (Not Null)

7. deliveries
   - id: INTEGER (Primary Key, Auto-increment)
   - order_id: INTEGER (Foreign Key -> orders.id, Unique)
   - driver_id: INTEGER // Can be linked to a driver table later
   - status: VARCHAR(50) (Default: 'pending') // pending, assigned, picked_up, in_transit, delivered
   - estimated_delivery: TIMESTAMP
   - actual_delivery: TIMESTAMP
   - current_lat: FLOAT
   - current_lng: FLOAT
   - route_coordinates: JSON // Array of {lat, lng} points for route tracking

RELATIONSHIPS:
-------------

- users -> addresses (One-to-Many)
- users -> orders (One-to-Many)
- addresses -> orders (One-to-Many)
- products -> order_items (One-to-Many)
- products -> inventory (One-to-One)
- orders -> order_items (One-to-Many)
- orders -> deliveries (One-to-One)

INDEXES:
-------

- users.email (Unique)
- users.id
- addresses.user_id
- products.wood_type
- products.is_available
- orders.user_id
- orders.status
- orders.tracking_number (Unique)
- order_items.order_id
- order_items.product_id
- deliveries.order_id (Unique)

ADMIN OPERATIONS SUPPORTED:
--------------------------

1. Product Management:
   - Create new products
   - Update product details (price, stock, specifications)
   - Delete products (soft delete by setting is_available = FALSE)
   - Manage inventory levels
   - Upload/manage product images

2. Order Management:
   - View all orders
   - Update order status
   - Manage delivery assignments
   - Process refunds/cancellations

3. User Management:
   - View user accounts
   - Manage user permissions (future admin roles)
   - Handle customer support requests

4. Analytics & Reporting:
   - Sales reports
   - Inventory reports
   - Customer analytics
   - Delivery performance

5. Content Management:
   - Update product descriptions
   - Manage specifications
   - Handle image uploads

DATABASE CONSTRAINTS:
--------------------

- All foreign keys with CASCADE delete where appropriate
- Unique constraints on email, tracking_number
- Check constraints on quantities (non-negative)
- Check constraints on status values (enum-like)
- Decimal precision for monetary values

BACKUP & MAINTENANCE:
--------------------

- Daily automated backups
- Point-in-time recovery capability
- Regular integrity checks
- Performance monitoring on key queries
- Index maintenance and optimization

This schema provides a solid foundation for the WoodShot platform with room for future enhancements like multi-tenant support, advanced analytics, and integration with external services.
